# Документация проекта

При изменении функций, API, настроек или запуска обновляйте корневой `README.md`
на русском языке. Это постоянное требование владельца проекта.

README должен быть понятен жюри хакатона и содержать:

1. Название проекта.
2. Краткое описание проблемы и целевой аудитории.
3. Реализованные функции и возможности.
4. Основной сценарий от входных данных до результата.
5. Технологии: языки, фреймворки, библиотеки, AI-модели, API и внешние сервисы.
6. Архитектуру и взаимодействие компонентов.
7. Пошаговую установку и запуск с командами.
8. Воспроизводимый сценарий проверки для жюри.
9. Источники данных и интеграции.
10. Фактические ограничения и нереализованные возможности.
11. Ссылку на публичную deployed-версию, если она существует; иначе явно укажите,
    что публичная ссылка отсутствует. Не выдавайте localhost за deployed-версию.

Описывайте только реализованное и проверенное. Секреты, реальные пароли и локальные
данные не включайте в документацию или Git. Детальные API-контракты можно вынести
в `backend/docs/` и связать ссылками с README.
