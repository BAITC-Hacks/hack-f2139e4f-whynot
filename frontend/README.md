# Tapsyrma — frontend

Готовый интерфейс платформы задач бизнеса и студенческих команд: создание карточки, уточнение деталей, прозрачный рейтинг готовности, публикация, предложения команд и подтверждение результатов. Интерфейс на русском языке.

Для жюри: [полная установка и локальный запуск](../README.md#7-установка-и-запуск-по-шагам)
и [сквозной сценарий проверки](../README.md#8-воспроизводимый-сценарий-для-жюри)
описаны в корневом README. Развёртывание на сервере не требуется.

Стек: React 18, TypeScript, Vite, React Router, Tailwind CSS и lucide-react. Компоненты интерфейса собственные. Состояние хранится в React; `localStorage` и `sessionStorage` не используются.

Добавлены регистрация бизнеса/студента, cookie-сессии, восстановление пароля,
редактируемый профиль целей и ценностей бизнеса, личная история задач и результатов,
а также запись/загрузка аудио при создании карточки. Настройки и сценарии:
[аккаунты, история и голос](../backend/docs/accounts-and-history.md).

Студент указывает уникальный ID, телефон, направления работы и навыки. После регистрации
он создаёт команду или вступает по названию и коду приглашения. Команда набирает 3–5 участников;
отклик отправляет лидер, а обсуждать задачу с бизнесом могут все текущие участники.

При регистрации и восстановлении пароля используется общий индикатор: «Слабый»,
«Нормальный» или «Хороший», с текстовыми требованиями и подсказками. Новый пароль должен
содержать 15–128 символов и не входить в серверный список распространённых паролей.
Пробелы и Unicode разрешены; обязательных цифр, заглавных букв или специальных символов нет.
Длина считается по Unicode после NFC-нормализации. Оценка сложности носит рекомендательный
характер и не заменяет обязательные требования. Вход со старым паролем сохраняется.

## Установка и запуск

Требуются **Node.js 22 или новее** и npm. Все команды ниже выполняются из папки `frontend/`.
В Windows используйте `npm.cmd` вместо `npm`, если PowerShell блокирует `npm.ps1`.

```sh
npm ci
```

Создайте `.env` по примеру `.env.example`, если собственного файла настроек ещё нет:

```sh
if [ ! -f .env ]; then cp .env.example .env; fi
```

В PowerShell:

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item -LiteralPath .env.example -Destination .env }
```

Существующие настройки сохраняются.

```sh
npm run dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173) и используйте этот хост для всей проверки и восстановления пароля. Порт фиксирован: при занятом `5173` Vite завершится с ошибкой, а не выберет другой порт. Backend уже разрешает origins `http://localhost:5173` и `http://127.0.0.1:5173`, но браузер хранит для них разные cookie. Для доступа с другого origin требуется настройка CORS на backend.

Backend запускается отдельно по [инструкции backend](../backend/README.md). Она описывает создание Python-окружения, установку зависимостей, настройки и заполнение демонстрационных данных через `python -m app.seed`. Проверка сервиса — [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health), каталог API — [http://127.0.0.1:8000/api/v1/catalog](http://127.0.0.1:8000/api/v1/catalog), Swagger — на [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs). `127.0.0.1` означает компьютер, на котором открыт браузер.

## Окружение

Актуальный пример хранится в `.env.example`:

```dotenv
VITE_API_BASE_URL=/api/v1
VITE_USE_MOCKS=false
```

| Переменная | Назначение |
| --- | --- |
| `VITE_API_BASE_URL` | По умолчанию `/api/v1`; Vite проксирует в `http://127.0.0.1:8000`. Cookie работают с тем же сайтом. |
| `VITE_USE_MOCKS` | Только строка `true` включает локальный демонстрационный API. По умолчанию используется настоящий backend. |
| `VITE_API_URL` | Совместимость со старой настройкой: базовый адрес сервера без `/api/v1`. Используется только при отсутствии `VITE_API_BASE_URL`; префикс добавляется автоматически. |

После изменения `.env` перезапустите Vite. Значения с префиксом `VITE_` входят в клиентскую сборку; секреты в них не помещаются.

### Демонстрация без backend

Укажите в `.env`:

```dotenv
VITE_USE_MOCKS=true
```

Перезапустите frontend. Мок-режим предоставляет бизнес-пользователя, команды, задачи разных уровней готовности и предложения. Данные находятся **только в памяти вкладки** и возвращаются к исходному состоянию после перезагрузки. Они не отправляются в настоящий API и не переносятся между режимами.

В реальном режиме задачи, профили, предложения и результаты сохраняются backend. После
обновления страницы аккаунт определяется по HttpOnly-cookie через `/auth/me`.

## Страницы и сценарий

В шапке доступны регистрация/вход или имя пользователя и выход. Каталог публичный;
создание задач и отклики требуют соответствующей роли. При выходе приватные данные очищаются.

| Маршрут | Что доступно |
| --- | --- |
| `/register`, `/login` | Аккаунт бизнеса или студента и вход. |
| `/forgot-password`, `/reset-password` | Запрос восстановления и новый пароль. |
| `/business/profile` | Компания, отрасль, цели, ценности и использование истории для AI. |
| `/business/history` | Личные карточки бизнеса, отклики и подтверждённые результаты. |
| `/student/history` | Отклики студента, решения, этапы и XP. |
| `/student/profile` | Личный ID, приватный телефон, несколько направлений работы и навыки. Старые аккаунты дополняют сведения здесь. |
| `/catalog` | Каталог опубликованных задач: фильтры по теме и готовности, сортировка по рейтингу сервера и страницы результатов. |
| `/tasks/:id` | Публичная карточка и форма отклика команды: идея, план, срок, необязательная HTTP/HTTPS-ссылка. |
| `/business/tasks` | Собственные черновики и публикации, количество откликов и переход к редактированию. |
| `/new` | Создание задачи из свободного текста и темы; три кликабельных примера слабого описания. |
| `/new/questions?task=ID` | Вопросы помощника, ответы, предлагаемая карточка и явное применение сведений. |
| `/tasks/:id/edit` | Редактирование всех десяти полей и темы, расшифровка рейтинга, подтверждение и публикация. |
| `/tasks/:id/proposals` | Предложения команд, приватный контакт лидера, обсуждение, принятие или отказ и подтверждение этапов. |
| `/team/profile` | Создание команды или вступление по коду, состав из 3–5 участников, приглашения и выход. Профиль команды редактирует лидер. |
| `/team/proposals` | Предложения текущей команды, решения бизнеса и обсуждения для всех участников. |
| `/team/progress` | Баллы XP, уровень команды и достижения по имеющимся данным. |
| `/recommendations` | Задачи с рейтингом от 40 и совпадениями по тегам профиля команды. |

Сквозная демонстрация:

1. Зарегистрируйте бизнес, заполните профиль, откройте `/new` и введите или продиктуйте описание.
2. Получите минимум три вопроса. Ответьте на известные вопросы; остальные можно пропустить.
3. Просмотрите предлагаемую карточку и нажмите «Применить и открыть карточку».
4. Дополните поля. Панель отдельно показывает подтверждённый рейтинг и возможный результат после подтверждения. Подсказки «до +N баллов» переводят к нужному полю.
5. Нажмите «Подтвердить карточку» после проверки сведений. Рейтинг обновится; достижение нового уровня сопровождается уведомлением.
6. Опубликуйте задачу. Она появится в каталоге; низкий рейтинг не мешает публикации или откликам.
7. Зарегистрируйте студента: имя, email, пароль, уникальный ID, международный телефон, одно или несколько направлений и навыки. Создайте команду и передайте её название и код ещё двум студентам.
8. Остальные участники регистрируются и вступают через «Вступить по коду». У лидера обновите состав. Когда участников станет 3–5, лидер сможет отправить предложение по любой опубликованной задаче.
9. Откройте «Обсудить предложение» в откликах. Участник команды и бизнес могут обменяться сообщениями; бизнес отдельно открывает контакт лидера.
10. Вернитесь в бизнес-кабинет и примите или отклоните предложение вручную. Можно принять несколько команд; автоматического выбора нет. После отказа переписка остаётся доступна для чтения.
11. У принятого предложения подтвердите этап и опишите проверенный результат. Команда получает XP: **прототип — 20**, **пилот — 30**, **передача результата — 50**. Повтор идентичного подтверждения не удваивает баллы.
12. Войдите как участник и откройте личную историю задач или прогресс команды. Личная история участия и результатов сохраняется после выхода из команды; чат бывшей команды становится недоступен.

Для проверки нескольких аккаунтов одновременно используйте отдельные профили браузера.
Приглашение показывается лидеру при создании команды или выпуске нового кода; новый код
заменяет старый. Телефоны не попадают в публичный список команд и не используются для рекомендаций.
Открытый чат получает новые сообщения каждые 5 секунд и поддерживает загрузку истории по частям.

Геймификация отражает существующие данные. Уровень команды выводится из `team.points`; достижения — из профиля, предложений, решений и баллов. Самостоятельного клиентского начисления XP нет. Рекомендации вычисляются во frontend по совпадениям тегов во всём доступном каталоге: это понятный фильтр интересов, не AI-оценка команд и не назначение исполнителя.

## Контракт и сохранение

Источник фактического контракта — [backend/docs/api.md](../backend/docs/api.md); дополнительные правила интеграции — [frontend-handoff.md](../backend/docs/frontend-handoff.md).

- JSON использует `snake_case`. Типы расположены в `src/types.ts`, запросы — в `src/api/client.ts`.
- `POST /tasks/:id/assist` возвращает предложение без сохранения. Оно применяется только по действию пользователя с учётом `based_on_revision`.
- `PUT /tasks/:id/card` заменяет карточку целиком. Frontend передаёт все поля и актуальную `expected_revision`, а затем использует новую `revision` из ответа.
- Подтверждение относится к текущей редакции карточки целиком. Backend не предоставляет отдельного подтверждения каждого поля. `/confirm` вызывается только после явного нажатия «Подтвердить карточку».
- Публикация — отдельное действие после подтверждения. Каталог показывает сохранённый опубликованный снимок. Последующие правки приватной карточки не меняют этот снимок до следующей публикации.
- `rating.score`, `rating.preview_score`, уровни и расшифровка приходят с backend. Frontend анимирует число и отображает подсказки, но не рассчитывает и не отправляет рейтинг.
- При `409 STALE_REVISION` введённый текст сохраняется на экране. Пользователь загружает новую серверную версию, сравнивает её со своей и явно выбирает, какую сохранить. Автоматической перезаписи правок нет.
- Во время сохранения формы блокируются от повторной отправки и изменения сохраняемых полей. Ошибки отображаются по-русски; доступны повторные действия.

Предварительная оценка пароля выполняется после паузы ввода около 500 мс через
`api.passwordStrength(password, signal?)`: `POST /auth/password-strength` с JSON
`{ "password": "..." }`. Тип ответа `PasswordStrength` хранится в `src/types.ts`:
оценка 0–4, уровень, русская подпись, `acceptable`, длина, проверки и подсказки.
Запрос идёт только в настроенный backend; пароль не попадает в URL, журналы frontend
или браузерное хранилище. Устаревшие запросы отменяются, их ответы не отображаются.
Если предварительная проверка недоступна, форма показывает «Не проверен» и позволяет
отправить пароль для обязательной серверной проверки при сохранении.

## Ограничения демо

Серверные cookie-сессии включены по умолчанию. `DEMO_MODE=false` отключает только тестовый
вход через заголовок. В mock-режиме регистрация, личные профили студентов, приглашения,
вступление в команды, чат и голос недоступны: нужен настоящий backend.
Без настроенного SMTP письма восстановления остаются локально в `backend/data/outbox`.

При `provider=stub` экран явно сообщает, что вопросы сформированы локальной заглушкой. `fallback_reason`, если он присутствует, показывается пользователю. Для OpenAI нужен ключ в `backend/.env`; Ollama настраивается отдельно по README backend. Помощник не публикует карточку и не подтверждает сведения за человека.

Рейтинг отражает полноту подтверждённого описания, а не доказанную достоверность или качество задачи. Загрузка файлов доступна для распознавания аудио; чат поддерживает текстовые сообщения. Вложений к задачам или чату, платежей и автоматического выбора команды нет. Ссылка на прототип открывает внешний ресурс, указанный командой.

## Проверки и сборка

Из `frontend/`:

```sh
npm run typecheck
npm run test
npm run build
```

`typecheck` проверяет TypeScript. `test` запускает Vitest: мок-API проверяется на подтверждение и публикацию карточек, ограничения доступа, устаревшие редакции и начисление этапов. Отдельные тесты проверяют контекст уточняющих вопросов, cookie-запросы, загрузку аудио, нормализацию профиля студента, контракты приглашений и объединение сообщений без пропусков. Проверки паролей охватывают задержку запросов, отмену устаревших ответов, сбой preview, NFC/эмодзи и отсутствие HTML-обрезания Unicode. Эти тесты не заменяют проверку реального backend и браузерного сценария.

После изменений выполните команды выше и сквозной сценарий через интерфейс.

Для просмотра собранной версии:

```sh
npm run preview
```

Адрес — [http://localhost:4173](http://localhost:4173). Если собранный frontend должен обращаться к backend с этого адреса, origin `http://localhost:4173` необходимо разрешить в CORS backend. Для стандартной локальной демонстрации используйте `npm run dev` на порту 5173.

## Файлы для передачи

Исходники находятся в `src/`: страницы — в `pages/`, формы и чат — в `components/`,
контракты и запросы — в `api/`, функции нормализации и их тесты — в `ui/`.
Передавайте также `package.json`, `package-lock.json`, конфигурацию Vite/TypeScript
и `.env.example`. `node_modules/`, `dist/`, `.vite/`, `.runtime/`, локальные `.env`
и `*.tsbuildinfo` в Git не включаются.

Актуальный список исходников можно получить из `frontend/`:

```sh
rg --files --hidden -g '!node_modules/**' -g '!dist/**' -g '!.vite/**' -g '!.runtime/**' -g '!*.tsbuildinfo' -g '!.env' -g '!.env.local' -g '!.env.*.local'
```

Для работы аккаунтов, команд, чата, истории и голоса нужна соответствующая версия backend
из этого же репозитория. Локальные данные и секреты в Git не включаются.
