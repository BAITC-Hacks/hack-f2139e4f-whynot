# Политика паролей и индикатор надёжности

Обязательные проверки выполняются backend одинаково при регистрации и
восстановлении пароля. Индикатор помогает выбрать пароль; окончательная проверка
всегда повторяется сервером при сохранении.

## Обязательные правила

- От **15 до 128 Unicode-кодовых точек** после нормализации NFC, включительно.
- Допускаются пробелы, Unicode и парольные фразы. Требований обязательно использовать
  цифру, заглавную букву или специальный символ нет.
- **Пароль целиком** сравнивается с локальным списком распространённых значений.
  Отдельные слова внутри длинной фразы не запрещаются по этому правилу.
- Для сравнения со списком используется `casefold`; при хешировании и входе регистр
  сохраняется. Начальные и конечные пробелы не удаляются.
- Оценка zxcvbn не является дополнительным обязательным порогом. `acceptable`
  определяется длиной и локальным списком; допустимый пароль может получить низкую оценку.

Список содержит словарь паролей zxcvbn и конечный набор дополнительных распространённых
длинных значений, повторов, последовательностей и вариантов названия сервиса.
Это не обращение к полной базе утечек и не доказательство, что пароль никогда
не был скомпрометирован.

При выборе правил учтены рекомендации
[NIST SP 800-63B-4, Passwords](https://pages.nist.gov/800-63-4/sp800-63b/authenticators/#passwords)
о длине, Unicode, сравнении целого пароля со списком и отсутствии обязательных
комбинаций символов, а также
[OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#password-strength-and-length).
Реализация отдельных рекомендаций не означает сертификацию или полное соответствие стандарту.

## Оценка в интерфейсе

В регистрации и восстановлении показаны индикатор, обязательные проверки и подсказки.
Используется серверная библиотека **zxcvbn 4.5.0** с локальными словарями. Оценка
предсказуемости не гарантирует устойчивость конкретного пароля.

| `score` | `level` | `label` |
| --- | --- | --- |
| 0–1 | `weak` | Слабый |
| 2 | `fair` | Нормальный |
| 3–4 | `strong` | Хороший |

Если обязательные правила не выполнены, оценка равна 0, `acceptable=false`.
Используйте собственную длинную уникальную фразу или генератор менеджера паролей.
Вставка из менеджера не запрещается. Не повторяйте пароль между сервисами.

## API предварительной оценки

`POST /api/v1/auth/password-strength`

JSON-тело содержит единственное поле `password` типа `string`. Пароль передаётся
в теле POST, не в URL. Проверка доступна до входа, но требует разрешённый `Origin`,
как другие маршруты `/auth`. Для стандартного локального интерфейса разрешён
`http://127.0.0.1:5173`.

Успешный ответ `200` имеет структуру ниже; значения зависят от введённого пароля:

```typescript
{
  score: 0 | 1 | 2 | 3 | 4;
  level: 'weak' | 'fair' | 'strong';
  label: 'Слабый' | 'Нормальный' | 'Хороший';
  acceptable: boolean;
  length: number;
  min_length: 15;
  max_length: 128;
  checks: Array<{
    code: 'min_length' | 'max_length' | 'not_common';
    passed: boolean;
    message: string;
  }>;
  suggestions: string[];
}
```

`length` — число кодовых точек после NFC, а не число байтов или UTF-16 единиц
JavaScript. Исходный ввод ограничен 1024 кодовыми точками. zxcvbn вызывается только
для допустимого по обязательным правилам значения длиной не более 128 после NFC.

Короткий, слишком длинный или распространённый пароль в пределах схемы возвращает
`200` с `acceptable=false`: это нормальный результат предварительной проверки.
Некорректная схема или ввод более 1024 кодовых точек возвращают `422`.

Оценка ограничена **60 запросами в минуту на IP** и двумя одновременными вычислениями
на процесс. Адрес берётся из соединения, произвольный `X-Forwarded-For` не считается
доверенным источником IP. Ошибки:

| HTTP / `error.code` | Причина |
| --- | --- |
| 403 / `UNTRUSTED_ORIGIN` | Нет разрешённого Origin |
| 422 / `VALIDATION_ERROR` | Неправильная форма или размер запроса |
| 422 / `WEAK_PASSWORD` | Недопустимые Unicode-значения, которые нельзя закодировать |
| 429 / `RATE_LIMITED` | Превышена частота запросов |
| 503 / `PASSWORD_STRENGTH_UNAVAILABLE` | Оценщик занят либо не смог вычислить результат |

Недоступность оценщика не отменяет серверную политику регистрации и сброса пароля.

## Регистрация, восстановление и вход

- `POST /api/v1/auth/register` независимо проверяет новый пароль.
- `POST /api/v1/auth/reset-password` применяет те же обязательные правила.
- Отклонение политикой возвращает `422`, `error.code=WEAK_PASSWORD` и безопасное
  сообщение о причине без копии пароля. Токен восстановления при этом не расходуется.
- После успешного восстановления одноразовый токен расходуется, старые сессии
  завершаются. Нужно войти с новым паролем.
- `POST /api/v1/auth/login` проверяет существующий пароль: старые аккаунты не обязаны
  менять его только из-за изменения минимальной длины.

Ошибки схемы, например неизвестное поле или неправильный тип, могут возвращать
`VALIDATION_ERROR` ещё до проверки политики. Во всех случаях пароль не усекается
до максимально разрешённой длины.

## Хеширование и совместимость

Новые пароли нормализуются в Unicode NFC перед подсчётом длины и хешированием.
Используется scrypt с индивидуальной солью и параметрами `N=131072`, `r=8`, `p=1`.
Новый формат хеша имеет префикс `scrypt-nfc`. Существующие хеши `scrypt` продолжают
проверяться по прежнему правилу без изменения сохранённых аккаунтов.

Одна операция scrypt требует примерно 128 МиБ памяти. Семафор разрешает не более
двух одновременных операций на процесс. В проверке участвует пароль целиком.

## Обработка данных и ограничения

Форма отправляет пароль только backend приложения. Предварительная оценка
не сохраняет его в БД, файле или ответе. Пароли не передаются OpenAI, Ollama, SMTP
или внешнему сервису проверки утечек. Ответы `/auth` имеют `Cache-Control: no-store`.
Для публичного сервера требуется HTTPS.

Лимиты запросов находятся в памяти процесса и сбрасываются при перезапуске;
для нескольких workers требуется общее хранилище. Проверка не заменяет MFA,
защиту устройства и управление сессиями. В этом MVP MFA и подтверждение email
не реализованы.

Реализация находится в [app/passwords.py](../app/passwords.py). Актуальные модели
доступны в [Swagger](http://127.0.0.1:8000/docs) запущенного сервера.
Запуск и сценарий для жюри — в [корневом README](../../README.md).
