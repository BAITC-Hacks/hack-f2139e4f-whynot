# Студенты, команды и общение с бизнесом

## Границы MVP

Каталог остаётся открытым, рейтинг задачи считается по прежним критериям, бизнес
вручную выбирает одну, несколько или ни одной команды. Баллы начисляются только за
подтверждённые этапы. ID, телефон и другие персональные сведения не участвуют в
ранжировании или AI-подборе. Расширение добавляет набор команды и текстовое обсуждение
отклика; файлов, уведомлений и отдельного проектного трекера нет.

## Регистрация и профиль

Бизнес регистрируется как раньше. Студент отправляет в `POST /api/v1/auth/register`:

```json
{
  "name": "Имя студента",
  "email": "student@example.com",
  "password": "your-long-unique-password",
  "role": "student",
  "username": "sana_developer",
  "phone": "+77010000001",
  "positions": ["Backend", "Frontend", "Собственная специальность"],
  "skills": ["Python", "React"]
}
```

`username` — уникальный публичный ID из 3–32 латинских букв, цифр и `_`, начинается
с буквы. Регистр и начальный `@` нормализуются: `@Sana_Developer` и `sana_developer`
занимают один ID. Внутренний `actor.id` остаётся неизменным при редактировании ID.
Телефон: `+`, код страны и 10–15 цифр; пробелы, скобки и дефисы удаляются.
Номер сохраняется для контакта, подтверждение по SMS не выполняется.
Специальности: 1–10 значений до 80 символов, навыки: 1–30 до 100 символов.
Можно выбрать несколько специальностей и написать свои; повторы убираются.

`GET /students/profile` возвращает `{actor_id,username,phone,positions,skills}`
только владельцу. `PUT /students/profile` принимает четыре редактируемых поля без
`actor_id`. У старого аккаунта без профиля возвращаются пустые поля: перед созданием
команды, вступлением или новым откликом их нужно заполнить.
Новая регистрация больше не создаёт личную команду автоматически.

## Команда от 3 до 5 участников

Студент состоит в одной текущей команде. Создатель становится лидером и входит в
общую численность. Команда из одного или двух человек находится в наборе; отправлять
отклики можно только при составе 3–5. Минимум не мешает создать команду и пригласить
остальных. Шестой участник не может вступить, включая одновременные запросы.

| API `/api/v1` | Действие |
| --- | --- |
| `POST /teams` | Создать команду: `{name,interests,skills,technologies}` |
| `GET /teams/me` | Своя команда, участники, готовность и роль текущего студента |
| `PUT /teams/me` | Лидер редактирует название и теги существующей команды |
| `POST /teams/join` | Вступить: `{name,invite_code}` |
| `POST /teams/me/invite` | Лидер выпускает новый код; прежний перестаёт работать |
| `POST /teams/me/leave` | Участник выходит; одиночный лидер может удалить команду без откликов |
| `GET /teams` | Общие профили и баллы без телефонов и кодов |

Вступление требует одновременно названия и инвайт-кода. Код выдаётся лидеру при
создании или замене; в БД хранится его хеш. Если код потерян, лидер выпускает новый.
Ответ личной команды содержит `members`, `member_count`, `ready`, `is_leader`.
Состав показывает имена, ID, специальности и навыки без личных телефонов.
Отправлять отклик и редактировать профиль команды может лидер. Остальные участники
видят отклики и результаты команды и участвуют в обсуждении.
Лидер не может просто выйти, оставив других участников или отклики без владельца.

Состав фиксируется для каждого нового отклика. Личная история `/students/history`
сохраняет эти отклики после выхода; вступивший позже студент не получает в личную
историю предыдущие работы команды. Командные баллы остаются у команды.
`GET /proposals/mine` показывает отклики текущей команды для совместной работы;
он отличается от личной истории участника.

## Контакт лидера и чат

`GET /proposals/{id}/contact` возвращает `{name,username,phone}` лидера. Доступ есть
у владельца задачи и текущих участников откликнувшейся команды. Контакты не входят
в публичный каталог, общий список команд или AI-запросы.

`GET /proposals/{id}/messages?after_id=0&limit=100` возвращает:

```json
{
  "items": [{
    "id": 1,
    "proposal_id": "proposal-id",
    "sender_id": "actor-id",
    "sender_name": "Имя",
    "sender_role": "student",
    "body": "Уточним формат пилота?",
    "created_at": "2026-09-23T10:00:00Z"
  }],
  "has_more": false
}
```

Сообщения идут по возрастанию `id`; следующая порция запрашивается после последнего
полученного ID. `limit` от 1 до 100. `POST /proposals/{id}/messages` принимает
`{body}` длиной 1–4000 символов и возвращает сообщение с кодом 201.
Сообщения сохраняются в БД и показываются как обычный текст.
Чат доступен владельцу задачи и текущим участникам этой команды. Посторонним
возвращается 404. После отказа переписку можно читать, отправка закрывается.
Интерфейс обновляет открытое обсуждение периодическими запросами. Лимит отправки:
30 сообщений за минуту на пользователя.

## Обновление существующей базы и проверка

Новые таблицы создаются при старте. Для существующих команд владельцы становятся
лидерами и участниками; чужие аккаунты автоматически не присоединяются. Для старых
откликов достоверно известен только прежний владелец команды, поэтому исторический
состав при переносе содержит его. Карточки, отклики, решения и баллы сохраняются.

Сценарий проверки: зарегистрировать трёх студентов → лидер создаёт команду → двое
вступают по названию и коду → лидер отправляет отклик на опубликованную задачу →
бизнес видит телефон лидера и отвечает в чате → вручную принимает предложение →
подтверждает этап → все три участника видят результат в личной истории.
Отдельно проверить отказ шестому участнику и отсутствие доступа у чужого бизнеса.

## Почта для восстановления пароля

В приложении используется одноразовая ссылка, не цифровой код. Сервер создаёт
случайный токен, хранит только его хеш и отправляет ссылку на email аккаунта.
Ссылка действует 30 минут; использование меняет пароль и завершает старые сессии.
`MAIL_MODE=file` сохраняет тестовое письмо в `backend/data/outbox` без отправки.
Для настоящей почты нужен SMTP отправителя; адрес получателя может быть любым.

Gmail не обязателен. Для Gmail доступен SMTP `smtp.gmail.com`, порт 587, STARTTLS.
Нужны двухэтапная аутентификация и пароль приложения, если этот способ разрешён
для аккаунта. Настройки в локальном `backend/.env` (секреты не отправляйте в чат):

```dotenv
MAIL_MODE=smtp
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_STARTTLS=true
SMTP_USERNAME=your-service-account@gmail.com
SMTP_PASSWORD=your-app-password
MAIL_FROM=AI Sana <your-service-account@gmail.com>
FRONTEND_URL=https://your-project.example
```

Для локального теста `FRONTEND_URL` оставляют `http://127.0.0.1:5173`; для сайта
указывают реальный адрес. После смены настроек backend перезапускается.
Официальные инструкции: [SMTP Gmail](https://support.google.com/a/answer/176600?hl=en),
[пароли приложений Google](https://support.google.com/accounts/answer/185833?hl=ru).
