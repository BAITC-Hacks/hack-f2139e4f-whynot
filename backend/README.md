# AI Sana — backend

FastAPI-сервис проекта TaskRank: аккаунты бизнеса и студентов, карточки с уточняющими
вопросами и рейтингом, команды, отклики, приватный чат, подтверждённые этапы и история.
Стек: Python 3.12+, FastAPI, Pydantic, SQLAlchemy 2, SQLite.

**Жюри начинает с [корневого README](../README.md):** раздел 7 содержит получение
ветки `backend`, запуск двух серверов и устранение ошибок; раздел 8 — пошаговую проверку
через интерфейс с ожидаемыми результатами. Публичный деплой не требуется.
Эта инструкция предназначена для отдельного запуска и проверки API.

## Запуск на Windows

Команды выполняются в PowerShell из корня скачанного репозитория. Нужен Python 3.12+;
проверьте его командой `python --version`. Если после установки команда не находится,
откройте новое окно терминала. Можно заменить первый `python` на `py -3`, если он
выбирает подходящую версию.

```powershell
if (-not (Test-Path -LiteralPath .venv)) { python -m venv .venv }
.\.venv\Scripts\python.exe -m pip install -c backend/requirements.lock -e './backend[dev]'
Set-Location backend
if (-not (Test-Path -LiteralPath .env)) { Copy-Item -LiteralPath .env.example -Destination .env }
..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Активация venv не нужна. Команда копирования сохраняет существующий `.env`;
не заменяйте рабочие настройки шаблоном. `requirements.lock` фиксирует проверенные
версии прямых и транзитивных зависимостей. Установка и запуск из чистой копии
проверены на Windows с Python 3.14; frontend — с Node.js 24.

## Запуск на macOS/Linux

Из корня репозитория; команды приведены для Python 3.12+, но отдельно на этих ОС
не запускались:

```sh
python3 --version
[ -d .venv ] || python3 -m venv .venv
.venv/bin/python -m pip install -c backend/requirements.lock -e './backend[dev]'
cd backend
[ -f .env ] || cp .env.example .env
../.venv/bin/python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

## Локальные настройки и проверка запуска

Для основного сценария внешние интеграции не нужны. Стандартные значения
`backend/.env.example`:

```dotenv
DATABASE_URL=sqlite:///./data/ai_sana.db
DEMO_MODE=false
COOKIE_SECURE=false
FRONTEND_URL=http://127.0.0.1:5173
CORS_ORIGINS=["http://localhost:5173","http://127.0.0.1:5173","http://localhost:3000"]
AI_PROVIDER=stub
MAIL_MODE=file
MAIL_OUTBOX_DIR=data/outbox
```

Backend читает `.env` именно из каталога `backend`, поддерживая UTF-8 с BOM.
Переменные окружения процесса имеют приоритет над файлом, включая пустые значения.
При этом относительные пути БД и почты зависят от текущего каталога, поэтому запускайте
сервер из `backend`: тогда данные находятся в `backend/data/ai_sana.db`, письма —
в `backend/data/outbox`. После изменения `.env` остановите сервер и запустите снова.

- Проверка сервиса и БД: http://127.0.0.1:8000/health — ожидается `status: "ok"`.
- Swagger: http://127.0.0.1:8000/docs.
- OpenAPI: http://127.0.0.1:8000/openapi.json.
- Публичный каталог: http://127.0.0.1:8000/api/v1/catalog — до создания/seed задач пустой.
- AI-контракт: http://127.0.0.1:8000/api/v1/ai/contract.

Frontend запускается отдельно на `http://127.0.0.1:5173` и проксирует `/api/v1`
на порт 8000. Открывайте приложение всегда через один хост: cookie для `localhost`
и `127.0.0.1` различаются. Для другого origin изменяются CORS, `FRONTEND_URL` и, при
смене backend-порта, адрес прокси в `frontend/vite.config.ts`.

Вход использует серверную HttpOnly-cookie, которую браузер получает после регистрации
или логина в интерфейсе на порту 5173. Swagger удобен для изучения контрактов и публичных
GET-запросов. При стандартных настройках auth-запросы и изменения через Swagger на 8000
могут получить `403 UNTRUSTED_ORIGIN`: этот origin не включён в разрешённые адреса.
Проходите регистрацию и действия с данными через UI. Авторизованный пользователь
видит только разрешённые ему карточки, контакты и историю.

Остановить сервер можно через `Ctrl+C`. БД и настройки сохраняются; повторный запуск
использует ту же команду Uvicorn. Обновление через `git pull --ff-only` и повторная
установка зависимостей описаны в [разделе 7 корневого README](../README.md#7-установка-и-запуск-по-шагам).
Для обновления не требуется удалять БД, письма или `.env`.

## Демонстрационные данные и API-сценарий

Обычная проверка интерфейса использует `DEMO_MODE=false` и собственные зарегистрированные
аккаунты. Для синтетического набора отдельно включите `DEMO_MODE=true` в `backend/.env`
и перезапустите сервер. Из `backend` в другом терминале выполните:

```powershell
..\.venv\Scripts\python.exe -m app.seed
..\.venv\Scripts\python.exe scripts/demo.py
```

В macOS/Linux:

```sh
../.venv/bin/python -m app.seed
../.venv/bin/python scripts/demo.py
```

Первая команда добавляет **5 отдельных черновиков, 5 опубликованных карточек
с рейтингами 20/55/80/90/100, 5 команд по три участника и 5 предложений**.
Повторный seed не перезаписывает эти записи. Все данные синтетические, ссылки
`example.com` служат примерами, а не работающими прототипами.

Вторая команда требует работающего сервера на стандартном порту 8000. Она создаёт
новую задачу, получает минимум три вопроса, показывает рост рейтинга **0 → 100**,
публикует карточку, отправляет предложение от `student-1`, вручную принимает его
от имени бизнеса и подтверждает прототип: **+20 XP**. Скрипт сохраняет существующий
профиль команды и при необходимости добавляет двух синтетических участников.
Обе команды проверены против локального сервера со `stub`.

Демо-вход через `X-Actor-ID` работает только при `DEMO_MODE=true` и только для
синтетических пользователей без зарегистрированного аккаунта. Это режим API-сценария:
у seed-пользователей нет паролей для формы входа. Новые аккаунты не получают владение
этими задачами или командами. После проверки верните `DEMO_MODE=false` и перезапустите
сервер; зарегистрированные аккаунты продолжат работать, seed-данные останутся в БД.

## Автоматические проверки

Из `backend`:

```powershell
..\.venv\Scripts\python.exe -m pytest -q
..\.venv\Scripts\python.exe -m ruff check .
..\.venv\Scripts\python.exe -m ruff format --check .
```

В macOS/Linux замените путь к интерпретатору на `../.venv/bin/python`.
Тесты используют отдельные БД, изолированы от пользовательского `.env` и переменных
интеграций, блокируют реальные HTTP/SMTP-запросы. Они не меняют демонстрационные данные,
не отправляют настоящие письма и не расходуют OpenAI-кредиты.

Проверяются права и изоляция пользователей, аккаунты/сброс пароля, профили, лимиты
состава и приглашения, рейтинг и публикация с нулевым баллом, неизменность публичной
версии до перепубликации, конфликты редакций, принятие/отказ, этапы и повторное начисление
XP, личная история после выхода из команды, чат и конкурентный отзыв доступа,
AI-контекст/fallback, аудио, фильтры и seed. Это не проверка доступности внешних сервисов;
реальные OpenAI и SMTP требуют отдельного запуска с действующими настройками.

## AI-вопросы, голос и бизнес-контекст

По умолчанию `AI_PROVIDER=stub` — обозначенная локальная заглушка, разрешённая кейсом.
Она выбирает минимум три вопроса по незаполненным полям и переносит явные ответы
в предлагаемую карточку. Семантический анализ заглушка не выполняет.

Для OpenAI заполните `OPENAI_API_KEY` действующим ключом в локальном `backend/.env`,
выберите `AI_PROVIDER=openai` и перезапустите backend. Стандартные модели:
`OPENAI_MODEL=gpt-4o-mini` и `OPENAI_TRANSCRIPTION_MODEL=gpt-4o-mini-transcribe`.
Промокод на кредиты не является API-ключом. Ключ хранится только на сервере и не должен
попадать в Git, frontend или `VITE_*`. Подключение и диагностика подробно описаны
в [разделе 9 корневого README](../README.md#9-данные-и-интеграции).

Для вопросов используется Responses API со структурированным JSON и `store=false`.
Модель получает описание, категорию, текущую карточку, ответы, последние 40 вопросов,
профиль компании и до пяти её прежних подтверждённых/опубликованных карточек.
Контакты из прежних карточек не включаются в исторический контекст. Отключение истории
в профиле убирает прежние задачи, но сохраняет явно заданные цели и ценности компании.
Промпт запрашивает 3–5 приоритетных вопросов, до восьми для сложных задач.

«Уточнить с учётом ответов» запускает следующий раунд; ответы дополняют поля карточки.
История вопросов текущего раунда находится на экране frontend; после перезагрузки
остаются явно сохранённые поля задачи. Помощник не выдумывает факты, не подтверждает
и не публикует карточку. Результат `/assist` сам по себе не сохраняется в БД.

При успешном запросе к модели ответ содержит `provider=openai`. `/health` показывает
выбранного провайдера и наличие ключа (`openai_configured`), но не проверяет ключ
или доступность модели. Timeout, HTTP-ошибка, неверный JSON и несоответствие схеме
переключают вопросы на `provider=stub` с `fallback_reason`. Промпт, входная и выходная
схемы, примеры и правила fallback доступны в `/api/v1/ai/contract` и [app/ai.py](app/ai.py).

Адаптер Ollama доступен для вопросов при `AI_PROVIDER=ollama`, `OLLAMA_BASE_URL`
и `OLLAMA_MODEL`: нужен отдельно запущенный сервис с установленной моделью.
Голосу при любом `AI_PROVIDER` нужен OpenAI-ключ. Аудио до 10 МиБ передаётся в API
распознавания и не сохраняется в БД приложения. Если распознавание недоступно,
интерфейс сообщает ошибку и позволяет продолжить обычным текстом.

Уместность живых AI-вопросов оценивается отдельно: сравните описания задач магазина,
учебного процесса и доставки, ответьте на первый раунд и проверьте учёт новых сведений
во втором. Автотесты проверяют контракт и передачу контекста, а не качество реальной модели.

## Аккаунты, восстановление и приватность

Новые пароли проверяются по длине 15–128 символов после NFC и локальному списку
распространённых значений; индикатор zxcvbn служит подсказкой. Хеширование scrypt
требует примерно 128 МиБ памяти на операцию, одновременно выполняются до двух.
Нет обязательного состава символов, MFA или подтверждения email/телефона.
Подробный контракт: [политика паролей](docs/password-policy.md).

При `MAIL_MODE=file` письмо восстановления сохраняется в `backend/data/outbox/*.eml`;
оно не отправляется на email. Откройте последнее письмо и перейдите по ссылке на
локальный frontend. Ссылка одноразовая, действует 30 минут; успешная смена пароля
завершает существующие сессии. UI-сценарий и чтение `.eml` без почтового клиента есть
в разделе 8 корневого README. SMTP не нужен для этой проверки; для настоящей отправки
есть [инструкция SMTP](docs/student-teams-and-chat.md#почта-для-восстановления-пароля).

Студент состоит в одной текущей команде. Только лидер команды из 3–5 участников
отправляет новые предложения. Доступ к чату и контакту лидера зависит от текущего
состава и владельца задачи; личная история — от состава, зафиксированного при отклике.
Выход из команды закрывает чат, но не удаляет личную историю. Новый участник получает
доступ к чату текущей команды, не наследуя чужую личную историю. После отказа бизнеса
чат остаётся только для чтения. Телефоны остальных участников не раскрываются.

## Ограничения и документация API

Рейтинг считает заполненные подтверждённые поля, а не достоверность или качество текста.
Публикация разрешена с любым баллом. Подбор задач для команды использует теги и навыки,
отбирая задачи с рейтингом от 40; это не AI-ранжирование.

Это локальный MVP на SQLite. Ограничения частоты запросов хранятся в памяти процесса.
Таблицы создаются при запуске; предусмотрено восстановление состава старых команд,
но полноценный инструмент миграций схемы не подключён. Чат опрашивается каждые пять
секунд; WebSocket, вложения в чат/карточку и отдельный проектный трекер не реализованы.
Загрузка аудио для распознавания реализована отдельно.
