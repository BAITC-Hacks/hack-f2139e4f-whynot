# AI Sana — backend

Рабочая основа MVP: черновик → уточняющие вопросы → редактирование → подтверждение →
рейтинг → публикация → отклик → ручное решение бизнеса.

Стек: Python 3.12+, FastAPI, Pydantic, SQLAlchemy 2, SQLite. Проверено на Windows / Python 3.14.
Данные сохраняются в `backend/data/ai_sana.db`, если запускать из `backend`.

## Запуск на Windows

Из корня репозитория, PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -c backend/requirements.lock -e './backend[dev]'
Set-Location backend
Copy-Item .env.example .env
..\.venv\Scripts\python.exe -m app.seed
..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Если `.env` уже настроен, сохраните его значения. Активация venv не требуется.
`requirements.lock` фиксирует проверенные версии прямых и транзитивных зависимостей.

Для macOS/Linux: `python3 -m venv .venv`, далее используйте `.venv/bin/python`
из корня или `../.venv/bin/python` из `backend`; файл настроек копируется через `cp`.

- Swagger: http://127.0.0.1:8000/docs
- OpenAPI: http://127.0.0.1:8000/openapi.json
- Проверка сервиса и БД: http://127.0.0.1:8000/health
- Каталог: http://127.0.0.1:8000/api/v1/catalog

Для другого frontend origin измените `CORS_ORIGINS` в `.env` — это JSON-массив.

## Демо и проверка

Сервис при запуске создаёт таблицы и демо-пользователей. `python -m app.seed` добавляет
5 отдельных черновиков разной полноты, 5 опубликованных карточек с рейтингами
20/55/80/90/100, 5 команд и 5 предложений. Повторный запуск не перезаписывает эти записи.
Все данные синтетические; ссылки `example.com` служат примерами, а не настоящими прототипами.

В отдельном терминале, из `backend`, при работающем сервере:

```powershell
..\.venv\Scripts\python.exe scripts/demo.py
```

Скрипт создаёт новую задачу, показывает рост рейтинга 0 → 100, публикует её,
отправляет предложение от `student-1`, принимает его от имени бизнеса и подтверждает этап.
Если профиль этой команды уже существует, скрипт сохраняет его.

Проверки из `backend`:

```powershell
..\.venv\Scripts\python.exe -m pytest -q
..\.venv\Scripts\python.exe -m ruff check .
..\.venv\Scripts\python.exe -m ruff format --check .
```

Тесты используют отдельные БД и не изменяют демонстрационные данные.
Проверяются полный сценарий, границы рейтинга, права, публикация с нулевым баллом,
сохранность опубликованной версии, устаревшие записи, повторные подтверждения этапов,
фильтры, seed и обработка некорректных ответов AI.

## AI

По умолчанию `AI_PROVIDER=stub`: это явно обозначенная локальная заглушка, разрешённая
условиями кейса. Она выбирает минимум 3 вопроса по незаполненным полям и переносит
пользовательские ответы в предложенную карточку. Заглушка не является LLM.

Для OpenAI создайте `backend/.env` из `backend/.env.example`, если файла ещё нет
(он исключён из Git), и укажите в нём:

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4o-mini
AI_TIMEOUT_SECONDS=30
```

Перезапустите backend после изменения `.env`. Ключ хранится только на сервере: не добавляйте
его во frontend, переменные `VITE_*` или Git. Исходное описание и поля карточки отправляются
в OpenAI Responses API со
структурированным JSON и `store=false`. В ответе `/assist` будет `provider=openai`, если
модель успешно вернула вопросы. `GET /health` показывает выбранного провайдера, но не ключ.
Без ключа или при ошибке API ответ переключается на `provider=stub` с `fallback_reason`.

В качестве локальной альтернативы доступен адаптер
[Ollama API](https://github.com/ollama/ollama/blob/main/docs/api.md).
Для него нужен отдельно запущенный Ollama с установленной моделью:

```dotenv
AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=имя-вашей-установленной-модели
AI_TIMEOUT_SECONDS=30
```

Модель генерирует вопросы в JSON по заданной схеме. В каждом запросе она получает
описание, название, категорию с возможными отраслевыми аспектами, актуальную карточку,
ответы, критерии готовности с весами и последние 40 вопросов текущей задачи.
Промпт просит выбрать 3–5 приоритетных уточнений (до 8 для сложных задач), опираться
на конкретный процесс, учитывать уже известное и уточнять расплывчатые ответы.
Кнопка «Уточнить с учётом ответов» начинает следующий раунд; введённые сведения
дополняют карточку и сохраняются между раундами. История вопросов живёт в текущем
экране frontend; после перезагрузки остаются только явно сохранённые поля карточки.
Шаблонная заглушка не выполняет семантический анализ; для персональных вопросов
нужен ответ с `provider=openai` или `provider=ollama`.

Карточка собирается только из
исходного текста и явных ответов человека: LLM не дописывает в неё факты.
Неверный JSON, неподходящая схема, повторяющиеся вопросы, timeout и HTTP-ошибка
переключают ответ на `provider=stub` с объяснением `fallback_reason`.
Промпт, вход и JSON Schema выхода доступны в `GET /api/v1/ai/contract` и [app/ai.py](app/ai.py).
Результат `/assist` не сохраняется автоматически. Реальное качество вопросов зависит от
выбранной модели; адаптер проверен тестовыми HTTP-ответами, запуск с LLM требует её настройки.

Для проверки качества с подключённой моделью сравните три описания: «Остатки магазина
проверяем вручную» (retail), «Обратная связь студентов теряется в чатах» (education)
и «Маршруты доставок составляем вручную» (logistics). Вопросы должны относиться к
соответствующим процессам. Затем сообщите формат и период данных и запросите следующий
раунд: модель должна уточнить неизвестные детали, учитывая этот ответ.
Автотесты проверяют передачу контекста и сохранность данных; уместность вопросов
реальной модели оценивается отдельно по этому сценарию.

## Ограничения первого этапа

Авторизация демонстрационная: заголовок `X-Actor-ID` выбирает роль. Проверки владельца и роли
есть, но знание другого ID позволяет переключиться на него. Для публичного запуска нужно
заменить эту зависимость проверкой сессии/JWT. `DEMO_MODE=false` выключает демо-вход и блокирует
защищённые операции до подключения настоящей авторизации.

Рейтинг оценивает заполненность подтверждённых полей, а не истинность или качество текста.
Бизнес подтверждает содержимое вручную. Таблицы создаются через `create_all`; миграции
для изменения существующей схемы пока не добавлены. Полный проектный трекер,
рекомендации, регистрация и загрузка файлов остаются вне первого этапа.

Подробнее: [архитектура](docs/architecture.md), [API для frontend](docs/api.md).
